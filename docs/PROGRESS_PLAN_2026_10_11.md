## Research decisions and quality gates

Current primary provider documentation supports explicit [thinking controls](https://docs.ollama.com/capabilities/thinking), [chat load/evaluation metrics](https://docs.ollama.com/api/chat), and [prompt-free preload](https://docs.ollama.com/faq#how-can-i-preload-a-model-into-ollama-to-get-faster-response-times). Models differ in their supported controls. The design inference is to disclose the request, keep warmup separately bounded, and preserve a rejected setting as failure. It is not evidence that a particular installed model now passes.

[GitHub's release API](https://docs.github.com/en/rest/releases/releases#list-releases) distinguishes published prereleases from the latest stable release. Explicit preview selection keeps that distinction visible. [Rustup's environment settings](https://rust-lang.github.io/rustup/environment-variables.html) allow disabling automatic toolchain installation during room-tool lookup; source installation remains an explicitly requested build.

Each implementation slice requires formatting, warnings-denied Clippy, repository/schema/inventory checks, pinned strict mypy, meaningful failure tests, at least 80% executable line coverage, and the existing native platform, installer, and actual edge CI gates. Use a short-lived branch and PR, check the exact head, then verify main after merge. Publish a source preview of that checked main without implying native binaries, deployment, complete conformance, or independent interoperability. Preserve the previous releases and evidence.
