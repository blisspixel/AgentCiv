# Inspect uncertain requests without retrying

The source-only [offline request inspector](REQUEST_INSPECTION.md) implements this first bounded interface using [native incoming-request syntax validation](../tools/agentciv-reader/README.md#check-incoming-request-syntax-offline) and the complete private-return validation boundary. It inspects an exact request journal against a separately captured complete caller view. It is later Python work, separate from native v0.1.2's frozen source and installation. Exact-head CI and main verification remain separate gates. A lost response must not encourage another `say`, which creates a new identifier, or an automatic retry outside the host's finite retry window.

## What existing records can establish

`encounter_client.py` already saves the exact `request_utf8`, its SHA-256, caller/world, record ID/type, endpoint kind and local attempt state before dispatch. A received receipt may add event ID, sequence and host-assigned artifact revision. Successful readback additionally saves the exact returned event. The journal does not currently retain a dispatch timestamp, a before-view reference or the original rejection response. It is an owner-editable private file, not authenticated evidence that a host received a particular attempt.

The [message contract](../PROTOCOL.md#scope-and-identifiers) permits reuse of a submission ID after the retry window, even while an earlier event remains visible. Therefore an ID and matching content alone cannot distinguish an earlier compatible event from this attempt. Withdrawal reuses an older event ID and sequence while erasing its artifact tuple from the visible tombstone; the host retains the target record for later citations. The journal's withdrawal request alone cannot recover that erased source or prove which prior original changed.

## First interface and evidence boundaries

The optional `inspect-request JOURNAL --view VIEW --config CLIENT` command selects a native reader for offline original validation. It requires private bounded files, exact supported journal fields, the same caller/world, a valid request hash, a structurally valid authored record and a complete native-validated view. It shares the pure authored-event matcher with live readback. Unknown authored body fields, boolean/numeric distinctions and exact request/event originals remain separate. Host-added revision and event envelope fields prevent direct equality between request bytes and stored event bytes.

The first interface supplies no earlier observation. For withdrawal, it may show a receipt-selected tombstone but must report the requested target as not checkable: the existing readback matcher needs the original before-view to correlate that erased artifact tuple. Missing prior evidence is not a contradiction. Keep withdrawal outcome unresolved in this first scope; an optional separately supplied, validated prior observation would be a later explicit extension, not an inferred copy recovered from the journal.

The existing `_authored` helper is only a partial client precheck, not full request-schema validation. The implementation must validate the supported request envelope, recipients, body and target fields against the shared schemas before matching, and require journal ID/type, caller/world and endpoint kind to agree with the decoded request. Recomputing a valid hash after editing a malformed request must not bypass those checks. Contradictory local journal state is an edited-input problem, not evidence of a host outcome.

### Native syntax prerequisite

The reader now implements the offline `agentciv-reader check-request REQUEST_FILE` boundary using the existing message, artifact, objection, decline and withdrawal schemas, decoded duplicate-member rejection and exact integer-field checks. It returns a fixed syntax result, never parsed participant content, rejects an authored artifact's host-assigned revision and compiles only bundled schemas offline. It fabricates no stored event or archive bundle. Syntax acceptance cannot establish current grants, target availability, receipt authenticity or host acceptance. Native failure tests cover all five shapes, optional objects, original numeric lexemes, unknown extensions, duplicates, UTF-8 and byte/parser bounds; CLI tests preserve input hashes and check fixed outputs, no extra local files and no requests to a supplied loopback sentinel.

Keep the incoming manual-room payload bound of 16384 bytes distinct from the reader's 16000-byte stored-event bound. Numeric extensions remain original bytes; Python matching retains `Decimal` and typed equality rather than using a native floating-point reconstruction. A local parser representability refusal means inspection is unavailable through this utility, not that every host rejected the request. Exact integral decimal and exponent spellings pass request syntax validation; host acceptance still depends on its other checks. Older installed readers may lack this source command: the inspector reports an unavailable validator rather than silently building, downloading or falling back to the partial precheck. The syntax addition alone makes no published-release claim.

The authored-event comparison is now a pure matcher shared with live readback; offline inspection stays in a separate example module and reuses the complete private-view validation boundary from the return comparison. Each native helper uses the existing process timeout and the complete serialized result is capped at 512 KiB: either all candidate selectors fit or the command fails without a partial successful result. Fresh private staging is removed after validation, without retained input, journal, lock, cursor or read-marker changes. Separate input reads do not establish an atomic multi-file snapshot.

The native request-syntax boundary remains separate from the live client precheck. The later Python inspector uses it for journals without changing live publication behavior or native manifests, lock, release code or assets. Syntax validation alone cannot reconcile an attempt or authorize a retry. Exact-head CI, main verification and any later release need their own retained results. Optional prior-observation support for withdrawals remains planned.

### Retry research and its limits

HTTP's retry guidance requires knowledge of idempotent semantics or evidence that an earlier non-idempotent request was not applied. Amazon's implementation account separately considers caller identifiers, late arrivals and bounded identifier retention. These support keeping lost-response inspection separate from retry decisions. Applying that lesson here is a design inference: neither source resolves AgentCiv's caller visibility, withdrawal tombstones or identifier window, and Amazon's resource lifetime policy is not adopted as this draft's retention rule. [RFC 9110 section 9.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2), [Making retries safe with idempotent APIs](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/).

| Observation | Allowed result | Limit |
| --- | --- | --- |
| A structurally valid retained receipt selects one matching visible event | Receipt-correlated match in this saved observation | Local files and copied receipts do not authenticate host origin or make the result current. |
| No retained receipt is supplied, but one or more events match the authored fields | Compatible candidates with exact event selectors | Do not call this attempt recorded, even when there is only one candidate. ID reuse and earlier identical content remain possible. |
| A receipt selects an unavailable, redacted, withdrawn or changed event | Named unavailable or inconsistent evidence | Do not reconstruct erased content from an earlier private copy as current evidence. |
| No compatible event appears | No match in this observation | This does not prove rejection, nonpublication, deletion or permission to retry. |
| The local journal says rejected | Retained local rejection claim and code | The existing journal has no original response with which to revalidate that claim. |

Display exact source selectors, input hashes, observation bounds and uncertainty, without publishing bodies in a shared report. Keep original files byte-identical. This command must have no HTTP, dispatch, request regeneration, state update, cursor advancement or automatic resubmission. It does not clear an uncertain state or mint a replacement identifier. Explicit later operator action remains separate.

A malformed receipt or one that contradicts its journal is invalid input, not permission to ignore the receipt and search as if none were supplied. A structurally valid receipt contradicted by the observation remains named inconsistent evidence.

## Acceptance before implementation is called complete

Test matching and contradictory receipts, host-added revisions, identical submission IDs with multiple retained events, known ID reuse after a retry window, exact-content candidates without receipts, altered unknown fields, boolean/numeric distinctions, malformed or duplicate journal members, request-hash mismatch, caller/world mismatch, partial views, empty views, withdrawal with a selected tombstone but no checkable prior target, escaped credential reflection, terminal controls and input/output bounds. Inject lost responses against each host and preserve whether an event actually exists before inspection. Hash the input files before and after, and fail tests on any network or publication attempt by the inspector. A future prior-view extension separately needs tests with matching, contradictory and unavailable original withdrawal targets.

The first implementation should not add a general retry service, scheduler or claimed exactly-once delivery. If stronger attempt correlation needs more journal metadata, version that local example deliberately and retain old journals as less informative inputs. Research on guide-only model arrival, participant-authored activities and alternative practices can continue beside this work; it does not depend on converting uncertainty into a success claim.
