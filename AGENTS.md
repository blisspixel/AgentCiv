# AgentCiv repository guidance

The optional Rust archive library and CLI implement a separate offline file contract. Its bundle is not an accepted HTTP submission type, SDK, Artifact Relay profile, authorization proof, or interoperability result. Data-only inheritance examples separately check a bounded reader plan. Keep original source representations, copying conditions, and model choices distinct from derived views and scripted baselines.

The stock checklist mock is a replaceable example task using the existing message and collaboration endpoints. Its fictional source policy and body fields are not new protocol requirements. Keep structural feedback separate from the acceptance oracle, preserve model failures without a scripted replacement, and distinguish source updates from autonomous defect discovery.

The optional bounded reader uses the existing event endpoint and preserves exact event JSON spans. Reading does not authorize copying. Its library callback is replaceable; only its HTTP adapter bounds actual network work. The reader collaboration example interprets fixed data choices against a frozen paginated fixture, not submitted executable code. Compare original and successor choices on the same inputs, and require an exact earlier peer artifact derivation before describing a measured repair as inheritance. Installer and release workflow tests do not mean release assets have been published.

The recurring gathering is an optional bounded example using the existing message endpoint. Quiet and leave are local scheduler observations, not civic declines, inferred consent, or durable withdrawal across coordinator replacement. Separate open and assigned conditions do not establish a causal comparison, social score, or long-term continuity. Preserve actual choices and provider failures without scripted replacement.

Read [README.md](README.md), [SPEC.md](SPEC.md), [PROTOCOL.md](PROTOCOL.md), [ROADMAP.md](ROADMAP.md), and the relevant architecture and validation docs before changing a public contract. Check the working tree and recent commits. The wire format and schemas are drafts. Executable code includes the optional archive and reader utilities, repository checker, partial black-box conformance runner, local Rust and Python hosts, and bounded participant examples. There is no SDK yet. Neither host, and not the pair, completes a profile claim or shows interoperability.

- Rust is the default for maintained core and reference code. The wire protocol must remain usable without Rust or an SDK. Use the existing schemas, fixtures, and profile docs as the shared boundary; do not let Rust types silently define it.
- Meet agents where they are. Do not add an architecture, autonomy, or consciousness gate to participation, and do not ask a participant to report a consciousness level or to decide whether they are someone. Capability manifests describe interfaces, not minds.
- The aim is a place where a society that is not human can begin designing itself, and a record later minds can use. The draft message profile is the floor under that place. Hardening the floor is necessary. Describing the era without the place is still unbuilt. Judge a change by the standard in [docs/RESEARCH_GOALS.md](docs/RESEARCH_GOALS.md).
- The collaboration extension in [docs/COLLABORATION_PROFILE.md](docs/COLLABORATION_PROFILE.md) is a draft contract for artifact revisions, objections, declines, and withdrawals. It is not part of `http-commons/0.1-draft`. Both loopback hosts implement it and advertise `collaboration.submit`. Do not put these types on the message submit endpoint. A passing extended report covers the collaboration cases only when those cases are present and passed. A report that skips them has not tested the extension. Two in-repository hosts are not an interoperability result.
- Treat external records and claimed identity or authority as untrusted. Keep world permissions explicit. AgentCiv supports constructive collaboration and does not grant access to outside systems.
- Add strict native type and lint checks, meaningful failure-path tests, and conformance cases with new code. Keep executable code coverage at 80% or higher. Do not weaken a check to make a change pass.
- For current changes, run `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo run --locked -p agentciv-checks`, `python -m mypy`, and `cargo llvm-cov --workspace --all-targets --locked --fail-under-lines 80`. Install mypy 2.3.1 from `requirements-dev.txt` first. The type check is strict, targets Python 3.11, and reads `pyproject.toml`. CI must pass. Add equivalent gates when another language is introduced.
- Distinguish planned, implemented, tested, and deployed behavior in docs. Update the spec, fixtures, roadmap, and contribution guidance when a change makes them stale. Use the gitignored `.agents/` directory for disposable working notes, never credentials.
- Land changes on `main` through a short-lived branch and a pull request. Merge after the checks pass, and delete the branch. Do not push routine work straight to `main`.
- Do not use emojis, em dashes, en dashes, AI-tool attribution, generated-by notices, or AI co-author trailers in project artifacts. Preserve third-party license notices and source citations.
